## What this is

This is a docs repository that consumes the revkit flake:

- **Content** lives here as MDX. Only registered components are allowed
  (ADR-0002); the CLI's authoring guards refuse hand-rolled HTML/CSS/JS.
- **Vocabulary** is defined once in `vocab/terms.yaml`; `<Term id>`
  references resolve there once the site build is wired in.
- **`revkit check`** enforces the five authoring guards from ADR-0005:
  component registry, no hand-rolled UI, vocabulary, links, plot
  structure — plus the vendored-code contract from ADR-0022.
- **`revkit serve`** will boot the local review daemon on `127.0.0.1`
  once M5 part 2 lands: rendering this `docs/` tree through revkit's
  packaged Astro/Starlight site (`revkit build`) and having `serve`
  mount the rail on the rendered pages. Tracked at
  [vig-os/revkit#57](https://github.com/vig-os/revkit/issues/57).
  Until then the daemon binary is available but has no rendered
  content to serve — the two commands below are what M5 part 1 ships.

## Two commands (M5 part 1)

```bash
direnv allow       # or: nix develop
revkit check       # run the authoring guards
nix build          # runs revkit check under a docs derivation
```

`revkit serve` (the local review daemon that mounts the rail on rendered pages)
is M5 part 2 — needs a `revkit build` step (not yet shipped).
