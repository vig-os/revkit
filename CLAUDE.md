# revkit — agent context

HTML-first review surface for the agentic era: agents author structured docs from a guarded component set, and humans
review them rendered, with comments that flow back to the agent (locally) or to GitHub PR reviews (hosted).

## Where things are

| What | Where |
|---|---|
| Architecture, user stories, agent interaction | `docs/designs/DESIGN-0001-revkit-architecture.md` |
| Decisions (one per file, `- Status:` line is the truth) | `docs/adr/NNNN-*.md`, index `docs/adr/README.md` (derived) |
| Story → ADR → milestone → issue traceability | `docs/FEATURE-MATRIX.md` |
| Roadmap | GitHub milestones M1–M7, tracking issues #6–#12 |
| Tooling to promote into vig-os/devkit | ledger issue #1, skill `/devkit_elevate` |

Before building a feature, find its story ID in the matrix and cite the ADR it implements. A change that contradicts
an ADR needs a new ADR (superseding), not a silent deviation.

## Environment

- Scaffolded by **vig-os devkit** (`.vig-os`: version, `direnv` mode, gitflow). Toolchain comes from `flake.nix`:
  enter with `direnv allow` (or `nix develop`). Node, Bun and the guardrails gates are in the shell.
- `flake.nix` pins `vigos` to `?ref=<DEVKIT_VERSION>`; bump both together (devkit MIGRATION.md lockstep rule).
- Devkit-managed files are regenerated on upgrade: edit only consumer-owned ones (`flake.nix` blocks,
  `justfile.project`, `.gitignore.project`, `README.md`, this file). `.claude/settings.json` is managed; put personal
  Claude settings in `.claude/settings.local.json`.
- devkit Claude plugin: `just claude-plugin` (pinned to `DEVKIT_VERSION`; `just claude-plugin dev` until a devkit
  release ships it).

## Committing

- Commit **inside the dev shell**: the hooks refuse outside it. **Never run `prek install`**: `core.hooksPath` is
  `.githooks`, and `prek install` overwrites the managed hook.
- Pre-commit config is generated by the flake (`hooks` in `flake.nix`), including the guardrails gates
  (`no-fake-impl`, `no-debug-leftovers`, `no-commented-code`, `no-hardcoded`, `duplication`, `derived-docs`,
  `adr-matrix`). Fix findings; don't bypass. `// guardrails-ok` only with a reason.
- Conventional commits with `Refs: #<issue>` (chore may omit). No AI attribution trailers.
- Gitflow: branch `<type>/<issue>-<summary>` from `dev` (types: feature, bugfix, docs, test, refactor, hotfix,
  release, chore), PR into `dev`. `main` only via the release train. Merge commits only.

## Conventions for revkit content (from ADR-0003/0004/0005)

- Prose is MDX; data (vocabulary, plots, questions) is JSON/YAML in side files.
- Use only registered components (`@revkit/components`); need a new one → `revkit escalate` / a
  `component-request` issue, never hand-rolled HTML/CSS/JS.
- Plots: `plots/<name>/spec.vl.json` + a sibling data file; no inline `data.values`.
