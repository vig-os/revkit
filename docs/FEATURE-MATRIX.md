The scope moved into the path — `GET /api/threads`, which named no repository and could therefore only answer org-wide, is **removed** and `GET <repo>/pr-<n>/api/threads` replaced it, so the scope is structural (no unscoped spelling to forget, no parameter to tamper with: `?repo=`/`?scope=`/`?log_key=` are 400 `unknown-parameter`). `events(seq, ts, payload)` is replaced by `review_logs(log_key, seq, …)` (`migrations/0003_scoped_logs.sql`), `D1ThreadStore` takes a **required** `logKey`, and `seq` is per review, so two `(repo, pr)` pairs cannot see each other's events and a `since=` cursor is per review. The gate **fails closed**: a guest on a gated route that names no scope is refused `403 invite-scope-unbounded` rather than reading "no scope" as "no restriction" — the condition that made the check select nothing. NOT done, and each item is the difference between this and shipped: **guests still cannot comment**, because `POST <repo>/pr-<n>/api/threads` stays 501 — `view`'s read-only rule is enforced by the GATE (403 `invite-read-only`) rather than by a write, which is how it is testable before the write exists; a repo-wide invite's holder is redirected to `/`, which classifies `unknown` and 404s — there is no repo-wide index page in this build, so a repo-wide invite can reach a review only by knowing its PR number (security-neutral, recorded); the `"Name (guest)"` GitHub mirror needs the App (slice 4, owner-gated #34); `revkit invite --type` is not a CLI command, since minting deliberately has NO HTTP route and is out of band for whoever holds D1 write access (`revkit deploy init`, slice 8); and ADR-0015's 30-day guest anonymisation ships as tested D1 logic with NO cron trigger wired, so guests are retained until slice 8 — a deliberately wrong direction for a privacy clock, recorded as such in the ADR-0015 amendment. **M4 slice 5b ships the client page**: the Worker serves ONE external, versioned, content-hashed script from `/_revkit/<version>/invite-<sha256>.js` — a path `script-src` already allowlisted and which resolved to a 404 until now — and that script rewrites the address bar to `/invite/` with `history.replaceState` **on load**, so the invite token survives in no `Location`, no body, no `Referer`, no log line **and no history entry**, including after a Back-navigation or a reload. Because the form posts the token in a hidden field, stripping on load costs the redemption nothing; the cost is that a guest who reloads before submitting must re-open the mail link, which recovers cleanly because a second open REUSES the browser binding rather than rotating it. With no inline script, `script-src` stays a **pinned path** — no `'unsafe-inline'`, no nonce, no `'strict-dynamic'` — and ADR-0012's `default-src 'none'` is untouched rather than relaxed; the policy is asserted as an exact source set, so widening it to the origin root is a red test. Every other name under `/_revkit/` is a 404 and **none of them redirects**. **How a browser page reads its CSRF token is answered by NOT needing one here**: the only state-changing call this page can make is the redemption, which deliberately has no CSRF check (a token binds a state change to an *existing* session, and a guest from a mail client has none), and the page that *would* need one — a guest rail posting a comment — does not exist, because the preview surface is 501 and the append is slice 4. So no `<meta>` and no script-readable cookie carry a token, which would have widened exposure to any injected script for a token nothing consumes; the token is on the redemption's response header and a same-origin `fetch` is all that would read it. An ADR-0012 amendment recording that mechanism is proposed with the PR, not applied here. The **`revkit invite` CLI** is still parked on an owner decision (#81: no Cloudflare credential path on the CLI, ADR-0014's credential file may not be read unattended, and minting remains library-only with no HTTP route).

**Constraint on slice 4, recorded here because slice 3 is the slice that made it
reachable.** `POST /api/threads` is still a single unscoped route: it answers
`501 not-implemented` for every caller, and the only thing distinguishing a
guest's write from an operator's is the *absence* of an invite. The moment that
route grows a write, a guest's comment is a `threads-append` row with no invite
id, no scope and no retention clock on it — which is precisely the record
ADR-0015 says must not exist in that shape. So: **guest writes may not go on
`threads-append`.** Before slice 4 implements that route, guest comments must
land somewhere that carries `invite_id` (and therefore the invite's scope, kind
and retention clock), and the route must resolve the guest's authority from the
ledger rather than from the absence of a session invite. This is a constraint on
the NEXT slice, not work in this one, and it is written down here so that slice
4 inherits it rather than rediscovering it.

| Q6 | Hosted threat model: CSP, CSRF, rate limits, fork isolation | ADR-0012 | M4 | [#9](https://github.com/vig-os/revkit/issues/9) | partial (M4 slice 5b moved the **client-asset half of the CSP clause**, which until now allowlisted a path that served nothing. The Worker now serves exactly ONE script — `/_revkit/<version>/invite-<sha256>.js` — compiled into the artefact from a committed, reviewed source (`src/client-script.ts`) rather than fetched from a PR artifact, so ADR-0012's "deployed by revkit's own release" holds in the sense that matters: the script comes from the running version. It is **content-addressed**: the filename is the SHA-256 of the exact bytes served, computed in the same request from the same string, so a page and the asset it names cannot disagree and a stale name is unreachable rather than merely unfetched — an OLD version's path 404s because the version segment is `env.REVKIT_VERSION` and nothing else, an unhashed or mis-hashed name misses by exact string equality, and **no `/_revkit/` path redirects**, which is the property that keeps `script-src` from widening (a browser drops a CSP source's path part after a redirect). It is served ungated with **no CSP of its own** (the embedding document's `default-src 'none'` is the control; a CSP on the script response would deny the document's own load of it), `nosniff`, `text/javascript; charset=utf-8`, and `immutable` — the naming scheme is what makes `immutable` true rather than optimistic. **With no inline script, `script-src` remains a pinned path**: no `'unsafe-inline'`, no nonce, no `'strict-dynamic'`, and the baseline `default-src 'none'` is untouched rather than relaxed to accommodate a script; the policy is asserted as an EXACT source set after a mutation run showed a denylist let `scriptPaths: […, "/"]` — widening `script-src` to the whole origin — pass every test. The script's single job is `history.replaceState` on the invite-open URL, which is what retires the token from browser history; it reads no cookie, writes no storage, makes no request, and so has no channel to exfiltrate the display name a guest typed — each absence pinned by name. **Still partial**: ADR-0012's CSRF clause is load-bearing on a reachable route (`POST /api/session/refresh`) but **no page can yet OBTAIN a token**, because the one state-changing call the invite page can make is the redemption, which deliberately has no CSRF check, and the guest rail that would need one is behind a 501 preview — so header-only delivery is available and unused rather than widened by a `<meta>` tag or a script-readable cookie. (`github` is deliberately NOT a recognised identity kind at all, so a session cannot reach the unscoped class by asking for it: re-pointing one yields `401 unrecognised-identity-kind`.) That was deliberately neither widened nor narrowed; a guest is confined to its invite's scope, and an `operator` stays org-wide until a provider can prove repo access. Earlier slices moved two of ADR-0012's four named clauses. **Rate limits now exist**: `packages/worker/src/rate-limit.ts` bounds invite redemption per invite token AND per client address, spending both buckets on every attempt so token rotation cannot escape the address half, never reading `X-Forwarded-For` (forgeable), and refusing with `429` + `Retry-After` — the ADR's "(Durable Object counters)" is amended to a D1 counter with the concurrency measurement behind it and the Durable Object recorded as the end state (slice 6). **The per-call invite clause is now implemented**, in two halves: revocation, expiry, scope and `can_comment` are re-decided from the invite row on EVERY authorized guest request (so revocation is immediate, including on sessions minted before it), and the same request must present the browser the invite was redeemed in. What is still partial, precisely: the GitHub-read clause needs the App (#34, slice 4); `POST <repo>/pr-<n>/api/threads` is still 501, so no CSRF-protected review WRITE ships (and guests still cannot comment); the R2 preview surface that would serve `<repo>/pr-<n>/` is still 501; and fork isolation remains. Also new in slice 5: the **org-wide read is gone rather than narrowed** — an operator session now reads one review per request, by URL, which is what a path-addressed surface means and is the safe direction; nothing in this build can enumerate a deployment's reviews, and the GitHub bridge (slice 4) is what will want to) |
